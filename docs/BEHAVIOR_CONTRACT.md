# 行为契约（Behavior Contract）

本文件定义插件的运行不变量。实现、配置说明与测试共同遵守下列行为。

## 1. 代次（Generation）与观察窗口

- 每会话单调代次，`advance` 只增不减；白名单移除后重加不会产生 ABA，旧任务
  持有的旧代次必然被任何检查点拒绝。
- 发送成功（DELIVERED）后，若代次未变，观察窗口（`last_proactive_observed_at`）
  必须至少推进到该事件时间，保留期间已消费的更新窗口；代次已变则不推进且有日志。
- 代次已变的旧任务：不得**发起**发送，不得推进观察窗口。但**已提交**的发送
  必须照常走 `record_proactive_attempt`：消耗冷却与日配额，且 DELIVERED 时
  同样写入 `last_proactive_text` 与 assistant 历史条目。因为提交是已发生的
  外部副作用：消息已经出现在群里，不记录会让下一次触发立刻重发同一会话，
  历史也会与平台实况不符。即：代次门只拦尚未发出的发送，已提交的发送照常
  记账。与 §2 的 UNKNOWN 语义同源。
- 会话失效（白名单移除/手动检查/插件停止）走同一失效入口，级联清理
  事件缓存、图片索引与任务注册。开启 `abandon_stale_on_new_message` 时的
  新消息只推进代次，不走这条级联（见 §6.3 与 §8）。
- `abandon_stale_on_new_message` 默认关。关闭时入口不因新消息推进代次，
  正在生成的主动回复继续生成，发送前检查最新消息的静默时间。
  判断期间出现新消息时，本轮结论作废，等待下一轮重新判断。
  新消息记录上下文、刷新静默并重排延迟检查。开启后，同一会话任何被入口接住的消息
  （含表情包、单独符号、空内容）都会推进代次，未发出的旧回复作废。白名单
  ABA、指令检查和停止路径不受此开关影响。

## 2. UNKNOWN 投递语义

- UNKNOWN（提交状态未知）不得自动重试、不得触发 after-send 钩子，但必须
  消耗冷却与日配额（防止同一事件被重复处理/重复直发），且不写入 assistant
  历史条目。观察窗口**仅在代次未变时**推进：代次已变说明该事件已被新消息
  取代，推进旧事件的窗口会掩盖新事件（与 §1 的代次门同源）。
- `False` = 确定未提交（如无可达平台目标）：不消耗任何额度、不推进观察窗口。
- 每次 logical attempt 由 pipeline 创建一个 `AttemptLedger`，ledger 带独立的 `ledger_id`（UUID4 hex）；生成、投递和唯一 record task 只传递同一 ledger 引用。`ledger_id` 只用于日志、任务关联和一次性记账诊断，不参与配置 revision，也不依赖进程级计数器。
- 提交状态以适配器是否真被调用为界：gateway 的前置步骤（预留、转 in-flight）
  抛错时适配器一次都没被调用，算确定未提交（同返回 `False`）；适配器入口之后
  抛出的异常一律归 UNKNOWN，仍算潜在投递，不得重试。工具直发预算在适配器之前
  扣减，提交后的异常不退还。

## 3. 工具策略（fail-closed）

- 主动运行默认空 allowlist：build 与 hook 之后注入的工具一律移除；工具集无法
  枚举或清理时**终止该次运行**（fail closed），绝不带病运行。
- 工具**名字读不到**同样终止该次运行：allowlist 模式下按 `<unnamed>` 违规拦截，
  denylist 模式下无从判断它是否在拒绝集合内——两种模式都不放行（与 allowlist
  分支的 `<unnamed>` 违规对称）。
- `proactive_inherit_tools` 继承宿主工具链，但宿主级危险能力（cron、浏览器/
  电脑使用、文件提取、知识库 agentic、shipyard_neo 的技能候选创建/评测/发布
  回滚）在任何模式下永远拒绝；denylist 无法强制时同样终止运行。
- `proactive_preserve_tool_schema` 仅在继承模式下沿用普通回复的工具 schema 模式，保留
  当前请求已有的危险工具定义（包括配置启用的定时任务工具）并拒绝执行；AstrBot
  `skills_like` 模式的原始执行工具集也须同步替换。缓存收益只在最终前缀一致且模型命中缓存时出现。
- 工具边界安装/恢复必须成对；只触碰事件自身字段，绝不修改共享宿主单例。
- 生成超时/取消/失败三类出口都不得丢失已发生的工具直发计数与文本。
- 隔离的 agent 保留发送 tracker；工具直发与普通事件发送都须在调用宿主 sender 前
  检查账本、会话代次、插件生命周期与局部闸门，不能因 tracker 保留而形成迟到发送。
- 继承工具使用本轮 Context 副本，事件发送与 Context 发送共用直发预算，
  Context 发送仅允许当前会话。

## 4. 局部闸门判定顺序（发送前重查）

`force` 跳过全部闸门；否则按序判定，任一不过即跳过发送：

1. 免打扰时段（`quiet_hours`，跨零点区间）
2. 日配额（`max_daily_replies_per_session`）
3. 静默时间（`min_silence_sec`）：按最新活动时间计算，生成和装饰期间的新消息重新计时。
4. 冷却（`cooldown_sec`）
5. 观察窗口已推进（该事件后已回复过）

免打扰、日配额、静默、冷却、观察窗口发送前重查最新状态。decorating hook await 返回后，
事件发送前重新检查局部闸门、代次和插件生命周期；停止发生在 hook 内时不得继续
`event.send`。装饰钩子抛异常不阻断发送：按出错时手上的链继续投递（可能含该钩子已
做的部分修改），异常只记 WARNING。

### 4.1 发送通道与装饰链边界

- 生成与投递共用同一份事件快照，消息 ID、发送者与正文在生成前固定。主动回复的
  extras 和结果槽独立于宿主入站事件；引用和 @ 始终指向本轮目标，提示词明确该目标。
  生成提示词使用本地消息快照，完整宿主历史通过 `req.contexts` 传入。主动回复投递后
  写入插件 `SessionState`；宿主对话记录由宿主 Agent 实现和历史插件管理。
- 带正文的手动检查在会话锁内写入测试文本，并绑定指令事件；无正文时使用最近消息事件。
- **两条发送通道**：事件在手上时走 `_send_via_event`（经宿主装饰链与发送后钩子），
  否则走 `context.send_message` 兜底——兜底**不经过装饰链**，装饰类插件对它不生效，
  也不 @ 人（没有可用的 sender_id）。「事件在手上」= `_last_events` 里还留着该会话的
  最后一条入站事件；取不到有两种成因：该会话在本进程生命周期内还没收到过任何入站
  消息（重启后的首条主动回复、定时触发），或最近一条事件已被事件缓存按条数上限回收
  （`MAX_CACHED_EVENTS`，超限时优先摘非活跃会话）。
- **换链后的丢弃**：装饰钩子替换链之后若发送失败或被抑制，链上的内容（含装饰插件
  写入的首段）随之丢弃；装饰类插件只能从自己的补发机制补回剩余段，self 在该形态
  下记 WARNING（`decorating hook produced no result`）。

## 5. 终止与任务生命周期

- 插件生命周期由单一 owner 持有，共三种状态。`RUNNING` 允许新任务。`STOPPING` 阻止 spawn 并等待收敛。`DEGRADED` 表示存在超出硬停止窗口的 quarantine task，拒绝所有新检查（包括 `force=True`），需要重载插件或重启宿主才能恢复。
- 首个隔离任务使插件进入 `DEGRADED`。`_can_start_tasks` 按生命周期状态决定是否接受新任务；隔离注册表保留任务句柄，任务退出后移除。
- `terminate()` 开始后 spawn barrier 生效，新后台任务停止启动。
- 生成超时不硬取消 run_agent：先 `request_stop` 优雅收敛，宽限
  `GRACEFUL_STOP_GRACE_SEC` 后仍不退才兜底取消；调用方取消时同样收敛，
  不留孤儿任务（其工具直发会绕过预算与代次闸门）。
- 生成时限覆盖宿主装配、请求钩子、reset 与模型运行；隔离任务退出后再回收其运行状态。
- 判断阶段的模型解析和历史读取分别使用 `decision_timeout_sec`，识图保留独立预算。
- 终止路径对最终状态保存只等待一个 `TERMINATE_TASK_TIMEOUT_SEC` 硬窗口。写入超时则保留 critical task 在 quarantine、标记 `DEGRADED` 并让 terminate 返回，未完成的写入按失败处理。立即失败只记录 WARNING，不阻塞宿主停止。
- **超时窗口内被豁免的 pending critical task 按任务身份放弃后续写入**（`main._spared_critical_tasks` + `save_storage` 的身份判据）。宿主不等待隔离任务就构造新实例，那个慢写若落地会用陈旧快照覆盖新实例刚写出的 `state.json`。
- 这条判据取任务身份，全局 `_abandon_disk_writes` 只留给最终落盘自己超时的路径：全局标志会连同同一把锁内随后执行的最终落盘一起挡掉，静默丢掉「最后一次记录之后的内存变更」。
- `terminate()` 结束时置 `_terminated`（含被取消、取锁超窗放弃最终落盘、异常路径），此后本实例的任何落盘一律放弃。账本终态任务可以比关停窗口更晚收尾，它手里的快照必然陈旧。
- 延迟检查等待前次检查结束使用 release 事件；运行标记与 release 成对维护。等待必须**有界**：
  超时 + 轮次上限，闸门失同步只能降级为一次延迟或一次丢弃（丢弃记 WARNING），
  不得永久挂起（与 §11 B3 同源）。

## 6. 白名单变更与回滚

- add/remove 双写（配置文件 + 状态文件）：任一步失败 → 内存回滚 → 重写 →
  仍失败则告警并上抛；不得留下内存与磁盘不一致的中间态。
  **「失败」包含取消**：`CancelledError` 继承 `BaseException`，`except Exception`
  捕获不到它；只捕异常会让 `replace` 的单向销毁（代次已推进、会话状态
  已摘下）在磁盘未写的情况下定格，故回滚必须显式捕取消、并用 `shield` 防二次
  取消打断回滚自身。`/on` `/off` 与 webapi 的配置应用走同一形状。
- 移出白名单：代次 prune、会话锁/运行标记回收、内存会话状态清除、磁盘条目
  过滤（重启不复活）。
- 越权拒绝先行：非管理员写指令不得取消在途回复；只读指令保持在途检查。
  `check` 在两个入口中都先保存最近事件，再由动作自身执行 invalidate。
  内联入口的 add/remove/on/off 在权限校验后统一取消；宿主指令组中的 remove
  经白名单替换取消，off 经 `apply_enabled_topology` 取消，add/on 保留在途检查。
  两个入口的去重由 `COMMAND_HANDLED_KEY` 完成。

## 6.1 `/on` `/off` 的持久语义

- `/off` 与 `/on` **跨宿主重启保持**：双写 `settings.enabled` 与配置文件，
  失败按 §6 同一套纪律回滚（内存回滚 → 重写 → 仍失败告警并上抛）。
  若只改内存 `runtime_enabled`，重启即回落到持久 `enabled`：用户打完
  `/off` 以为已经关停，重启后插件继续发言且无从得知要再打一次。
- `runtime_enabled` 仍是独立字段：webapi 的 GET config 要能把它与持久
  `enabled` 分开暴露，前端全量保存才不会把临时态固化成持久配置。
- 回显文案含「重启后保持」，用户可见变更。

## 6.2 私聊主动回复开关

- `enabled_private_sessions` 默认开；总 `enabled` 仍是总电闸。
- 关闭后：消息入口不记私聊、不调度延迟检查；`session_check_guard`
  （`force=False`）与巡检跳过私聊。群聊白名单不受影响。
- 判定私聊的依据是 `session_group_id` 为空，与消息类型名无关。
- `/selfreply check` 走 `force=True`，关闭后仍可测；`/selfreply add` 仍可把
  当前私聊加入白名单。白名单只有一套。

## 6.3 新消息放弃旧回复开关

- `abandon_stale_on_new_message` 默认关。关闭时入口不因新消息推进代次；
  正在生成的主动回复继续生成，发送前按最新活动检查静默。新消息记录上下文、
  刷新静默，并重排尚未开始检查的延迟任务。
- 开启后：同一会话任何被入口接住的消息（含表情包、单独符号、空内容）推进代次，
  未发出的旧回复作废。
- 白名单移除、`/selfreply check`、插件停止仍走 `invalidate`，不受此开关影响。
- 不按消息类型拆第二套代次策略。

## 7. 配置解析

- 全部数值经 `as_int`/`as_float` 夹取（min/max），布尔严格化；白名单、提示词、
  历史缓存、日配额均有硬上限，防止垃圾配置造成 OOM/费用爆炸。
- webapi 未知配置键 fail loud（列出未知键拒绝），绝不静默吞掉。
- POST `/config` 必须带有效 `Content-Length`；缺失或无效返回 411，超过 1 MiB 返回 413，均在 JSON 解析前拒绝。
- 启动读取配置文件遇到 I/O 错误时可用宿主配置继续运行，但跳过规范化写回；损坏或非对象 JSON 会先备份，再按回退配置启动。
- 由 `ConfigSpec` 唯一拥有数值、枚举和字符串列表的机器规则。每个 list/set 必须声明最大条目数、条目长度、非法字符规则和空值策略。set 条目先去重并按 canonical 顺序排序，再执行容量上限，避免输入排列改变实际保留值。
- Web API 对非法条目拒绝；容量与数值边界按规格归一化，并在 `adjusted_fields` 返回实际被调整的键。磁盘加载使用同一规则过滤，只记录计数型 WARNING。正式键类型损坏时沿既有 legacy fallback 读取。
- GET `/config` 返回 `config_revision`：它是持久配置 canonical JSON（UTF-8、固定键排序、紧凑分隔符、集合排序）的 `sha256:<hex>` 摘要，不包含 `runtime_enabled`、Provider 列表或其他运行态；相同配置在重启后摘要稳定。
- POST `/config` 若带 `base_revision`，必须在 `_config_lock` 内先与当前摘要比较。不一致返回 `error_code=STALE_WRITE` 和当前 `config_revision`，不应用部分更新。成功响应返回完整 `config`、新的 `config_revision` 和 `adjusted_fields`。
- 不带 `base_revision` 的旧调用继续串行写入，迟到旧写覆盖不在防护范围内。
- 设置页初始配置加载完成前表单保持 `inert`。配置读取带请求 epoch，迟到或用户已编辑后的响应不覆盖控件；保存始终携带当前 `base_revision`。
- Bridge/fetch 保存超时或异常时进入“状态未知”，先刷新取得新 revision 再写入。`STALE_WRITE` 同样要求刷新。成功响应中的 `adjusted_fields` 显示对应字段标签。

## 7.1 本地图片读取与错误回显

- 本地图片放行的**唯一判据**是路径落在允许根内（插件 image_cache、宿主
  `<data>/temp`、WebChat 图片/附件目录、录制插件目录），在 `_file_to_data_url`
  一处收口。提取层的 `trusted_local_path` 只作分流提示，放行判断只看路径是否落在
  允许根内：宿主 aiocqhttp 用通用分支装配 `Image`，其 `file` 是对端可控的 OneBot
  原始值，`Image` 恒为非 Mapping 组件，提取层的信任推断条件因此总是成立，可被伪造。
- 已知限制：Telegram 配了自建 Bot API 服务器（`telegram_file_base_url`）时，
  `file_path` 是本地绝对路径且不在 `<data>` 下，该场景图片被拒，
  降级为纯文本主动回复。默认 HTTPS 配置不受影响。
- HTTP 响应只回通用文案 + 本模块自造的字段级校验文案；内部异常的 `str()`
  （含绝对路径、上游 SDK 原文）只进服务端日志。客户端可控输入不得反射回响应。

## 8. 缓存与清理

- 事件生命周期与图片生命周期分离：普通事件回收只调用
  `clear_event(umo, expected_active_at)`，且时间戳不匹配时不得删除新事件；它不删除
  保护窗口内的图片索引。白名单移除、命令失效和终止才调用 `clear_session`/`reset_all`
  清理图片索引。
- 图片索引有保护窗口：只清理过期源，窗口内源（`prepared_source`）绝不清除。
- 内存 data URL 按实际驻留的 base64 载荷字节计数，同时受全局和单会话预算约束；超限图片跳过并
  WARNING，不静默无限增长。Vision 描述 LRU 另受条目数和字节预算约束。
- 远程图片每跳重新解析并绑定已验证的公网 IP；原 hostname 继续用于 HTTP Host/TLS
  SNI，HTTP 客户端关闭环境代理，最多跟随 3 次重定向，中间响应体直接关闭；请求声明
  `Accept-Encoding: identity`，最终响应 `Content-Encoding` 非 identity 时拒绝并记
  WARNING：解压会绕过体积计数上限。
- 同时执行的阻塞图片 DNS 查询有界；超额请求直接降级，不能占满 AstrBot 共用的
  默认线程池。
- 事件缓存超 `MAX_CACHED_EVENTS` 即时回收，未超限时按 `EVENT_CLEANUP_INTERVAL_SEC`
  间隔回收；运行中/有待执行任务的会话事件不回收，上限因此是软的。
- 图片冻结缓存有年龄与容量双重上限，清理互斥串行；内容寻址文件通过临时文件
  `fsync` 后 `replace` 原子发布。
- 状态文件写盘：原子写（临时文件 + fsync + replace + 目录 fsync），损坏/版本不符文件
  备份后容错加载，不静默丢数据。

## 9. 日志纪律

- DEBUG：高频成功路径（消息捕获、发送完成、巡检结果、检查结果回显）。
- INFO：启用/终止、配置变更、清理结果、判断结果、生成模型、发送抑制与投递记账，
  以及图片不可用等降级原因。判断结果包含 `should_reply` 与理由，供排查未接话原因。
- WARNING：**静默降级但用户可感知**的数据异常。判据是「不记则无从定位」：
  会话历史 JSON 损坏 → `req.contexts` 留默认值 → 机器人带空上下文接话，
  用户感知为「失忆」，必须 WARNING。
  相对地，会话本身取不到属可接受降级，保持 DEBUG，避免噪音淹没告警通道。
- 远程图片被**地址策略**主动拒绝（私有网段、端口非法或非白名单、逐跳重解析后
  落回内网）记 WARNING，与网络故障的 INFO 分开：前者说明有对端在敲被拦的门，运维
  需要看得见，混在噪音里就失去意义。
- `last_decisions` 的 reason 经凭证脱敏，仍可能含至多 200 字用户原文（运营可见）：`state.json`
  本就持久化 recent 全文，此处沿用既有暴露面，取值见 `utils.DECISION_REASON_MAX_CHARS`；
  经 `/selfreply status` 呈现时折单行并截断至 60 字
  （`commands._RECENT_DECISION_REASON_MAX`，见 §13）。`GET /status` 只返回聚合计数，
  不返回会话标识或裁决原因。

## 10. 宿主兼容面

- 宿主私有 API 只经运行时适配层访问；缺失即拒绝加载并给出升级指引
  （版本下限见 `metadata.yaml` 的 `astrbot_version`）。
- 兼容检查锁定版本为硬门禁，最新版为漂移预警。

## 11. 共享容器身份

main 在装配段把若干可变容器（dict/set）的**引用**交给协作对象
（scheduler / session_coordinator / whitelist）。这些对象在构造时捕获容器
对象本身。由此产生三条承重契约：

- **B1：容器只能原地改，绝不属性重绑定。** 任何恢复/重置路径（`webapi._restore_plugin_state`
  与 `SessionGate.restore`）必须用 `clear()` + 原地写入
  （`update` / `setdefault` / 下标赋值）保持容器身份，禁止
  `plugin._x = {...}`。违反后果是静默的：回滚后 main 从新 dict 读、协作对象继续
  写旧 dict，该会话主动回复停止直到重启，且不抛异常、无日志。
  失效形态不止「忘了 clear」，也包括「换成新对象再赋值」。
- **B2：白名单变更的双写回滚必须把 prune 掉的会话状态放回原容器。**
  `whitelist.commit_change` 持久化失败时，除恢复白名单集合外，还必须
  `self._sessions.update(pruned)` 把移出时摘下的会话状态还原（配额、冷却、
  观察窗口）。少这一步会让「操作已失败」的会话丢掉历史，等价于配额被清零。
  回滚本身再失败时记 `logger.error` 并上抛（见 §6）。
- **B3：代次不回滚，锁表可恢复，运行集与 release 表按在途任务的 owner 存活推导。**
- 运行集是「某个在途任务正在跑」的租约，快照值在回滚时可能过期。
- release 表里等待者持有的是具体 `Event` 对象：按值恢复会制造孤儿事件（永久挂起），
  按身份恢复则带回陈旧的 `set` 状态（`while is_running` 每轮立即返回，紧密空转
  独占事件循环）。
- `SessionGate.restore` 因此把 `_running_owners` 里 owner 仍活着的会话判为运行中，
  再据此反推 release 表：仍在运行的 `clear()`（等待者重新挂起），已不运行的
  `set()`（唤醒，避免等一个不会到来的信号）。owner 已 `done()` 即判「检查已结束」，
  这是主判据；没有正在驱动调用的 task 时记 `None` = 未知，按保守方向保留标记，
  那种情况由 §5 的超时与轮次上限兜底。
- 照抄快照运行集会在两个方向上出错：把窗口内已结束检查的租约写回去（该会话从此被
  「已有判断任务在运行」永久拒绝），以及抹掉窗口内新起、此刻仍在跑的检查的标记
  （下一个检查与它真正并发）。锁表同理：快照之后才由 `lock_for` 创建、此刻仍被
  持有的锁必须并回去，否则在途检查丢失互斥对象。

共享容器由插件侧直接传给协作者（scheduler / session_coordinator / whitelist），
协作者保存同一对象的引用，容器内容按 B1 原地修改。`SessionGate` 的 release 表
由自身管理，恢复时按 B3 协调在途任务与等待者。

## 13. 运维端点定位

- GET /{PLUGIN_ID}/status（webapi._api_status）：**面板零消费、运维/排障专用**。
  返回生命周期与插件开关、白名单数量、代次与运行任务数量、任务和缓存规模、裁决总数，
  其中不含会话标识与裁决原因。前端把它与 /config 这类面板契约分开维护。
- 同一份裁决原因在聊天指令 `/selfreply status` 里也呈现（时间、接话/不接话、原因，
  原因折单行并截断 60 字）。两处同源于 `session_pipeline.record_decision` 的单点写入，
  判据与格式化口径只此一份；聊天窗口那份同样是只读的。

## 14. 引用、「@ 对方」与「已被回应」判定

### 14.1 引用（`quote_mode`）

- **默认关。** 开启后引用的是**这一轮生成依据的那条消息**。pipeline 在调用生成前
  冻结 `_last_events[umo]`，生成读 `state.recent` 与这行冻结之间没有 await，装饰
  目标与生成输入取同一时刻。判断阶段（识图 + 判断模型）到达的新消息以生成侧为准，
  在那里冻结会让引用指向一条生成从未依据过的消息。
- `model`：判断模型在裁决 JSON 里给出可选 `quote` 决定。模型未表态（手动检查、
  判断模型关闭）时按 `quote_probability` 兜底。`quote` 解析不出来归 None
  （=「模型没说」），整条裁决照常有效。
- `random`：全部按 `quote_probability`（0 从不引用、100 每次引用）。
- 引用组件在装饰钩子**之后**插入链首。取不到消息 ID 或组件构造失败时降级为普通
  发送，装饰性组件不影响投递结果与记账。
- 引用、@ 与**发送通道**锚同一条消息。该事件的结果槽早已结算，生成期间新到达
  消息的事件归宿主处理，借用它会因互相覆盖发出错误内容。
- context 兜底路径没有消息 ID，跳过引用。

### 14.2 @ 对方（`mention_mode`）

- **默认关（`off`）。** 三档：`off` 从不 @，`always` 每次都 @，`random` 按
  `mention_probability`（0 从不、100 每次）。
- **@ 目标唯一来源**：与引用目标同一条冻结消息的 `sender_id`，语义是
  「回应刚才说话的人」。每次只 @ 这一条消息的发送者，`sender_id == self_id` 时
  降级。取不到 sender_id 一律降级为普通发送。
- **与引用正交、不联动**：两个开关独立生效，可同时开启。链首顺序恒为
  `[Reply, At, ...正文]`（先插 At 后插 Reply），与 AstrBot 的装饰顺序一致。
  LLOneBot 会在引用后附加 @ 锚点，引用须置于正文 @ 之前。
- 插件添加引用或 @ 成功后，合并装饰钩子留下的同目标组件；@ 使用冻结目标的昵称。
- **`off`/`always` 不调用随机源**：不消耗随机序列，同批测试的随机数轨迹可复现。
- **是否 @ 由配置决定**：@ 属于投递形态，与「该不该接话」的判断内容分开，
  因此没有 `model` 模式，裁决 JSON 也不扩展字段。
- **装饰性组件的降级纪律与引用一致**：宿主链不可写、平台不支持 @、组件构造失败
  时静默降级为普通发送，投递结果（DELIVERED/UNKNOWN 分类）与 ledger 记账照常进行。
- **context 兜底路径没有 sender_id，跳过 @。**
- 插入位置在装饰钩子**之后**、最后一次代次复核（复核点 2/2）通过的同一处。两步
  插入都是同步的，**不新增 await 点**：「代次复核与 send 零 await」这条纪律不变。
  从最后一次复核到 send 之间插入 await 会新开竞态窗口，届时就地补一道复核。

### 14.3 其他

- **`skip_after_direct_call` 默认开。** 被 @Bot/唤醒的消息由 AstrBot 正常回复
  （不经过本插件），插件把它记为「这条消息之后 Bot 已经回应过」：同一批消息在此期间
  不触发主动回复，`last_active_at` 被下一条新消息推进后自动恢复。关闭后只更新活跃时间。
- 判断提示词里的聊天记录变量超预算时**保尾**（保留最新若干条），与生成路径
  `cap_context_text` 同口径，对齐默认模板「优先参考最近至少 8 条」的要求。
