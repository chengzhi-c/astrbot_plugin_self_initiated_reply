After receiving a message, the plugin waits a period of silence, then uses a **judge model** to decide whether to proactively chime in; replies go through AstrBot's main Agent pipeline, with tool boundaries tightened by default (relaxable). Direct `@Bot` mentions, wake words, and commands still go through the normal reply chain — the two paths never interfere with each other. Config and state live under AstrBot's data root directory; cross-platform group chats are stored as full UMO entries, and bare group IDs remain supported.

## How It Works

1. **Collect** — listens to normal messages in whitelisted sessions; content that explicitly asks to reply, send an image, or find an image is passed through first, while the rest goes to the judge model.
2. **Judge** — the judge model only answers "reply or not", outputting strict JSON:
   ```json
   {"should_reply": true, "reason": "a brief reason"}
   ```
3. **Reply** — the reply body is generated by AstrBot's main Agent / tool loop, with the full toolchain but restricted boundaries.

## Tool Boundaries

Proactive replies and `@Bot` normal replies are two independent paths. By default, the proactive path disables third-party plugin tools, Shell/Python, file read/write, browser, cron, skill management, memory writes, and cross-session sending; when the tool set cannot be verified, execution is refused outright (fail closed). The settings page offers "Allow inheriting plugin tools" to relax the boundary, but host-level dangerous capabilities (cron, browser/computer use, file extraction) remain disabled under all circumstances.

## Image Recognition (Optional)

Off by default. When enabled, text descriptions of the most recent images are attached during the judge or generation phase:

- The two switches are independent: **judge-model vision** (looks at images when deciding whether to reply) and **main-model vision** (looks at images when generating the reply body). The judge phase fires frequently, so enabling only main-model vision saves tokens. Each can be assigned its own Provider; within the same Provider, an identical image is described only once, and results are cached in runtime memory per Provider (about 50 entries, re-described after plugin reload/restart or eviction), preventing descriptions from leaking across Providers.
- **Sticker images can be skipped**: QQ OneBot `subType=1` stickers are excluded outright without calling Vision.
- Image snapshots go into the plugin's own `image_cache`; remote images are frozen in the background so they don't depend on expiring QQ CDN links. Real formats are validated by magic numbers, guarding against SSRF and forged paths.
- Descriptions only participate in judging as untrusted context; they are never written to history or state and cannot trigger tools. The cache auto-cleans by expiry and capacity, and the settings page has a "Clear now" button.

## Settings Page

A settings page inside the plugin detail page, covering: run switch and whitelist overview, context/delay/silence/cooldown parameters, judge model (Provider, temperature, timeout, prompt editing with live preview), whitelist UMO batch editing, and image cache cleanup.

The UI ships with light and dark themes — light "Boon of Compassion", dark "Court of Judgment", toggled in the top-right corner, defaulting to system preference:

**Judge model tuning** is the most frequently used entry point:

| Field | Description |
| --- | --- |
| Enable judge model | When off, ordinary messages no longer trigger proactive replies; explicit requests can still pass through |
| Judge model Provider | Defaults to the current session model; pick from the dropdown or enter manually |
| Judge temperature | Recommended `0.0 - 0.3`, lower is steadier |
| Judge timeout (seconds) | Recommended `20` seconds |
| Judge prompt | Supports `{session}` `{trigger}` `{bot_aliases}` `{latest_message}` `{recent_messages}` `{last_message_age_sec}` `{last_reply_age_sec}` variables with live preview on the right; leave empty and save to restore the default |

After changing settings, click "Save" and the page re-reads the server-side config. If you want to see the latest page assets after reloading the plugin or restarting AstrBot, hard-refresh the browser.

## About the Whitelist

The whitelist has two layers: AstrBot's global whitelist intercepts first, and only after passing it does the plugin whitelist decide whether to reply proactively. `/selfreply add` adds the whole group session. The "Advanced: Whitelist Session IDs" section supports batch editing — full UMO or bare group IDs.

<summary>📋 Commands (7 total, click to expand)</summary>

Only English command entries are registered, to avoid accidental triggers in daily chat:

| Command | Description |
| --- | --- |
| `/selfreply` | Show help |
| `/selfreply status` | Runtime status, judge model, whitelist |
| `/selfreply add` / `remove` | Add / remove the current session from the whitelist |
| `/selfreply list` | View the whitelist |
| `/selfreply check [content]` | Manually test one proactive reply |
| `/selfreply on` / `off` | Temporarily enable / pause |
| `/selfreply debug` | Current session, sender, trigger recognition info |

Forms like `@Bot selfreply add` are also supported. Note that `/selfreply on/off` is a temporary runtime state: saving plugin config in the official Dashboard triggers a hot reload that resets the temporary state, whereas saving from the plugin's own settings page does not.

<details markdown="block">
<summary>✅ Recommended Configuration (click to expand)</summary>

| Parameter | Recommendation |
| --- | --- |
| Judge temperature | `0.0 - 0.3` |
| Judge timeout | `10 - 30` seconds |
| Minimum context messages | `3 - 8` (default `5`) |
| Delay after message | `60 - 180` seconds (lower for testing) |
| Minimum silence seconds | `120 - 300` seconds |
| Cooldown seconds | `300 - 900` seconds |
| Max replies per session per day | `5 - 12` (`0` unlimited) |
| Max proactive reply length | `100 - 300` chars (`0` unlimited) |
| Image recognition | Off by default; groups heavy on stickers can enable "skip sticker images" |

"Ignore sender ID" can block specific users (including admins); the command path is unaffected.

"Log proactive reply content" is off by default to protect privacy; enable it in settings when troubleshooting.

<details markdown="block">
<summary>🛠️ Troubleshooting (no proactive replies? click to expand)</summary>

Check in order:

1. Is the session in the proactive-reply whitelist?
2. Is AstrBot's global whitelist not intercepting it?
3. Look at `/selfreply status`.
4. Check `should_reply` and `reason` in the logs.
5. Judge model not letting it through? Tune "judge prompt" and "judge temperature".

After changing plugin code, pages, or metadata, restart AstrBot or reload the plugin to apply.

</details>
